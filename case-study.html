309 scattered documents → one verified file

Anonymised. What matters here is not who it was for — it is how the count was checked, because that is the part almost nobody does.

The problem

Several years of documents existed only as attachments and share links inside email threads. Nobody could say how many there were. Two earlier attempts had produced folders that looked complete, and the only way to find out otherwise was to go looking for something specific and not find it.

The hard part of a job like this is never the collecting. It is being able to say, at the end, how many there were and how you know.

What was done

  1. Every thread was walked and every link and attachment extracted — including the ones further down in quoted replies, which is where the earlier attempts lost most of what they lost.
  2. Each document was fetched and stored with the thread and date it came from, so any row can be traced back to a source.
  3. Duplicates were removed by content, not by filename. The same document had been re-sent under four different names.
  4. Every document's word count was taken twice — once at the source, once in the final file — and compared.

The verification

Whatever appears below is computed by this page from the per-batch figures in its own source, not typed in as a total. That is deliberate: the thing being sold here is a number you can check, so the page checks its own — and if the two word counts disagreed, the box below would say so rather than printing a clean result.

It also means the page can admit when it has nothing to show, which is exactly what it is doing at the moment.

What could not be retrieved

They are listed in the delivery with the thread each one came from, so they can be chased by hand. A file that quietly omits them is a file that looks better and is worth less.
